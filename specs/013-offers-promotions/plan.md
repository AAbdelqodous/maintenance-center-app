# Implementation Plan: Offers & Promotions

**Branch**: `013-offers-promotions` | **Date**: 2026-05-03 | **Spec**: [spec.md](spec.md)

---

## Summary

Build an end-to-end offers & promotions feature. The backend introduces the `CenterOffer` entity with dynamically-computed status (no scheduled job — status derived from dates and a `cancelledAt` timestamp at query time). The frontend adds 4 new screens under the profile tab plus 3 reusable components and a new RTK Query slice. All text is bilingual. No existing files are broken; all backend changes are additive.

## Implementation Details

### Backend

#### CenterOffer Entity — key decisions
- `applicableServiceTypes`: `@ElementCollection` stored in `center_offer_service_types` join table (same pattern as `MaintenanceCenter.workingDays`)
- `cancelledAt: LocalDateTime` (nullable) — null = not cancelled; non-null = cancelled + timestamp
- `discountValue: BigDecimal` with `DECIMAL(10,3)` for KD precision
- Status NOT stored — computed in service layer from dates + `cancelledAt`

#### Status Computation
```java
private OfferStatus computeStatus(CenterOffer offer) {
    if (offer.getCancelledAt() != null) return OfferStatus.CANCELLED;
    LocalDate today = LocalDate.now();
    if (offer.getStartDate().isAfter(today))  return OfferStatus.SCHEDULED;
    if (!offer.getEndDate().isBefore(today))  return OfferStatus.ACTIVE;
    return OfferStatus.EXPIRED;
}
```

#### OfferRepository — custom queries
```java
List<CenterOffer> findByCenterIdOrderByCreatedAtDesc(Long centerId);

@Query("SELECT COUNT(o) FROM CenterOffer o WHERE o.center.id = :centerId " +
       "AND o.cancelledAt IS NULL AND o.endDate >= :today")
long countActiveOrScheduled(@Param("centerId") Long centerId,
                            @Param("today") LocalDate today);
```

#### OfferService — validation rules per method

**createOffer()**:
1. `endDate > startDate`, `endDate >= today`
2. `discountValue > 0`; if PERCENTAGE → `discountValue <= 100`
3. `countActiveOrScheduled(centerId, today) < 10` → else `IllegalStateException`
4. Set `currentRedemptions = 0`, `cancelledAt = null`

**updateOffer()**:
1. Compute status; if EXPIRED or CANCELLED → `IllegalArgumentException`
2. If ACTIVE: reject `discountType`, `discountValue`, `startDate`, `applicableServiceTypes` changes
3. If ACTIVE and new `endDate < current endDate` → `IllegalArgumentException` ("end date can only be extended")
4. Run same date/value validations as create for changed fields

**cancelOffer()**:
1. Compute status; if EXPIRED or CANCELLED → `IllegalArgumentException`
2. `offer.setCancelledAt(LocalDateTime.now())`; save

#### OfferController mapping
```
GET    /centers/my/offers           → getMyOffers(?status, ?page, ?size)
POST   /centers/my/offers           → createOffer(@RequestBody @Valid OfferRequest)   → 201
GET    /centers/my/offers/{id}      → getOffer(@PathVariable Long id)
PUT    /centers/my/offers/{id}      → updateOffer(@PathVariable Long id, @RequestBody @Valid OfferRequest)
PUT    /centers/my/offers/{id}/cancel → cancelOffer(@PathVariable Long id)
```

Center resolved from `SecurityContextHolder` principal → `centerRepository.findFirstByOwner(user)` (same pattern as other `/my/` endpoints).

#### Status filter in getMyOffers()
```java
// In service: filter after fetching (list is typically small per center)
List<CenterOffer> all = offerRepository.findByCenterIdOrderByCreatedAtDesc(centerId);
return all.stream()
    .map(o -> OfferResponse.from(o, computeStatus(o)))
    .filter(r -> status == null || r.getStatus() == status)
    .collect(toList());
// Wrap in PageImpl for consistent PageResponse shape
```

#### OfferForm Zod schema (key rules)
```typescript
const offerSchema = z.object({
  titleAr: z.string().min(1),
  titleEn: z.string().min(1),
  discountType: z.enum(['PERCENTAGE', 'FIXED_AMOUNT']),
  discountValue: z.number().positive(),
  applicableServiceTypes: z.array(z.string()).optional(),
  startDate: z.string().min(1),
  endDate: z.string().min(1),
  maxRedemptions: z.number().int().positive().optional(),
}).refine(d => d.endDate > d.startDate, {
  message: 'End date must be after start date', path: ['endDate'],
});
// discountValue <= 100 for PERCENTAGE validated server-side (too complex for cross-field Zod)
```

#### [id].tsx — Edit/Detail screen logic
- `isEditable = status === 'SCHEDULED' || status === 'ACTIVE'`
- `lockedFields = status === 'ACTIVE' ? ['discountType','discountValue','startDate','applicableServiceTypes'] : []`
- Cancel button visible only when `status === 'SCHEDULED' || status === 'ACTIVE'`
- Cancel: `Platform.OS === 'web' ? window.confirm(...) : Alert.alert(...)` before calling `cancelOffer(id)`
